# Astria Map Studio

React + TypeScript map editor with a Fastify/MySQL API, compatible with the verified Busta/JhonGanzEmu static database schema. This repository contains the modern implementation and its PNG/XML assets.

This modernization references AstriaMapEditor v2 by Zano and carries the supplied [GPLv3 license](LICENSE.md).

## Quick start

1. Install Node.js 22.12 or newer and run `npm ci --legacy-peer-deps` in this folder.
2. Copy `.env.example` to `.env`, point `DATABASE_URL` at the emulator's **static** database (`duty_estaticos_hero2` in the verified setup), and set a random `JWT_SECRET` and `ADMIN_PASSWORD`. The `.env` file is ignored by Git and is not included in the distribution ZIP.
3. Run `npm run build`, then `npm run server`. Open <http://127.0.0.1:3001> and sign in with `ADMIN_USERNAME` and `ADMIN_PASSWORD` from `.env`. For Vite hot reload, run `npm run dev` and open <http://localhost:5173>.
4. `npm test` runs codec/topology/SWF tests. `npm run schema:inspect -- duty_cuentas_hero2 duty_dinamicos_hero2 duty_estaticos_hero2` refreshes the complete table and column inventory.

The API checks the existing Atlanta emulator tables before starting and creates only additive `editor_*` tables. It saves maps to `mapas` with the exact 23 columns found in the user's database. It reads and writes teleport actions in `celdas_accion`, fight teleports in `accion_pelea`, and a single fixed group in `mobs_fix`; unrelated actions remain intact. See [Atlanta adapter](docs/ATLANTA_ADAPTER.md) and the [full schema inventory](docs/emulator-schema.json).

The PNG and XML assets live under `assets/`. The app serves on localhost by default and needs an existing Busta static database. See [Installation Busta](INSTALLATION_BUSTA.md) for a complete setup. The optional Docker Compose service also requires an existing Busta static database; set `DATABASE_URL` to a host reachable from inside the container (for example, `host.docker.internal` with Docker Desktop), then run `docker compose up --build`.

To add a viewer or editor after the first admin login, set `NEW_USERNAME`, `NEW_PASSWORD` (at least 12 characters), and `NEW_ROLE=viewer|editor|admin` in the process environment, then run `npm run user:create`. This command refuses to overwrite an existing account.

## Working features

- Create maps with the Astria cell count and blocked borders; open multiple tabs and warn on dirty close.
- Canvas isometric rendering with layers, grid/ID/cell modes, culling, zoom/pan, and tile image transforms.
- Brush, cell flag sweep, selection and multi-selection, trigger and end-fight linking across open tabs.
- Undo/redo, copy/paste, brush size, layer deletion, global tile delete/replace, `F` flip and `R` rotation.
- Asset pack browser with virtual scroll and legacy image origin metadata; atlas generation via `npm run atlas`.
- Map and cell inspector, geoposition grid and PNG export, monster fields, music/ambiance/background settings.
- JSON import/export, legacy DB import, Astria-generated FWS/CWS SWF import, legacy SQL export, JSON drafts in IndexedDB, two PNG thumbnails on save.
- JWT login, roles in the database, rate limiting, time-limited edit leases, version checks, history, and audit trail.

## Limits to know before production use

- `.ame` BinaryFormatter files are intentionally not deserialized. Import them through a trusted legacy Windows export to the DB, then use the DB import, or convert them to the documented JSON format.
- The SWF importer accepts the Flasm pattern generated by this Astria source. It rejects unrelated SWF variants and encrypted `mapData` inside SWF.
- The JSON document stores all editor fields. The SQL export contains the `mapas` row only; the live API also updates the supported action tables. Rows with unsupported or multiple action variants are preserved and cannot be edited through the simplified controls.
- Two existing map rows (7787 and 10986) have `mapData` lengths inconsistent with `ancho`/`alto`; import rejects them. The other 9,303 rows passed a no edit codec round trip.
- The emulator's `mapas`, `celdas_accion`, and `accion_pelea` tables use MyISAM, so MySQL cannot make their updates atomic with the InnoDB editor history. The API checks external changes before save and stores a prewrite snapshot in `editor_map_backups`; stop emulator writers while publishing map changes.
- Version conflicts are detected and the local draft is retained. Automatic cell-level merging is not implemented.
- The atlas generator writes packed PNGs and metadata. The interactive renderer currently loads individual PNGs through its image cache; switching the renderer to generated atlases is a later performance milestone.
- Interface text is French and the theme is dark. Full locale switching, screen-reader grid navigation, automated browser visual tests and production throughput targets remain on the roadmap.
